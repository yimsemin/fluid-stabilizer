# 조작 가이드 (비개발자용)

프로그램을 직접 다루는 법의 **유일한 출처**다. 키·버튼·서버 조작은 여기에만 쓰고 다른 문서는
링크만 건다. 개발 지식 없이 따라 할 수 있게 썼다.

용어: ① 강체 · ② 규칙기반 · ③ 학습 정책 · ④ 천장의 뜻은 [docs/README.md](README.md) "용어".

## 1. 시작하기

1. Unity Hub 에서 이 폴더 열기 (Unity **6000.5.10f1**).
2. 상단 메뉴 **FluidStabilizer ▸ Rebuild Play Scene**. (`PlayScene.unity` 는 git 에 없다 —
   빌더가 실행마다 id 를 다시 배정하므로 필요할 때 이 메뉴로 만든다.)
3. `Assets/FluidStabilizer/Scenes/PlayScene.unity` 을 열고 **Play ▶** 누르기.

씬이 이상하면 2번을 다시 한다.

## 2. 키 한눈에

| 키 | 동작 |
|---|---|
| **W / S** (게임패드 트리거) | 가속 / 제동 |
| **A / D** (왼쪽 스틱) | 조향 |
| **Space** | 스태빌라이저 켜기/끄기 |
| **0 ~ 5** | 스태빌라이저 선택: 0 강체(①) · 1 SFA · 2 SFA+적분(화면 표기 "Rule: PID", ②) · 3 특권 feed-forward(치트, 비교용) · **4 학습 정책(③, 서버 필요)** · **5 천장(④, 후행지식 재생)** |
| **M** | 슬로시 모델 전환: 진자 ⇄ 얕은물 (실행 재시작) |
| **G** | 도로 켜기/끄기: 평평 ⇄ 실제 도로 |
| **R** | 리셋 |
| **T** | 슬로모 (0.25×) |
| **Tab** | 카메라: 추적 → 측면 → 위 |
| **H** | HUD 자세히 보기 (가속도·도로·타이어·슬로시 에너지·전체 키 목록) |
| **P** | 주행 녹화 시작 / 다시 눌러 저장 |
| **L** | 최신 녹화 재생 (재생 중에는 운전 불가, `0~5` 로 스태빌라이저만 바꿔 같은 주행을 비교) |
| **C** | 3분할 비교 (6절) |
| **K** | 라이브 학습 패널 (8절) |
| **`** (백틱) | 설정 패널 (3절) |

3 번(특권)과 5 번(④)은 실제 센서가 줄 수 없는 정보를 쓰는 **비교 기준선**이다. 실시간으로 달성한
성능이 아니다.

## 3. 설정 패널 — 백틱 키

화면 오른쪽 위 "`` ` ``(백틱): 설정 패널" 을 눌러 연다. (키보드 `Esc` 아래, `1` 왼쪽)

- **도로 프리셋**: 평지 / 일반 고속도로 / 비포장 / 굽은 길 / 급경사 / 빗길 / 눈길.
  누르면 관련 값(거칠기·굽음·경사·접지력·채움)이 한 번에 바뀐다.
- **슬라이더**: 채움(fill), 탱크 높이, 도로 거칠기, 굽은 정도, 오르내림,
  접지력(낮을수록 미끄러움), **미끄러짐 격렬함**(미끄러진 뒤 얼마나 요동치나 —
  0 없음 / 0.5 순함(기본) / 1 이상 거셈), 운전자 종류/강도, 슬로시 모델.
- **[적용 (씬 재시작)]**: 바뀐 값을 `experiment.txt` 에 저장하고 시뮬을 다시 시작한다.
  **적용을 눌러야 반영된다.**
- **[되돌리기]** 파일 값으로, **[기본값으로]** 공장 초기값으로.

화면 왼쪽 위 HUD 에 지금 적용된 프리셋과 값이 표시된다. 적용했는데 HUD 가 그대로면 적용이 안 된 것.

`experiment.txt` (저장소 최상위)는 텍스트 편집기로 직접 고쳐도 된다. 패널과 파일은 같은 값을 본다.
그 밖의 값은 `Assets/FluidStabilizer/Core/Sim/SimulationConfig.cs` 의 코드 기본값이다. 탱크 내부
배플(`BaffleCountX/Y`, `BaffleLossCoeff`)은 패널에 없고 코드·실험 도구에서만 바꾼다 (얕은물 모델만 반영).

## 4. 화면 읽기

- 파란 flatbed 가 트럭, 그 위 탱크는 **개방 edge frame**(기둥 12개)로 그려져 안이 보인다. 스필하면
  프레임이 **빨갛게** 번쩍인다.
- 탱크 안 액체의 윗면이 슬로시 모델의 자유표면이다. **진자**: 두 1차 모드 각에서 나온 기울어진
  평면(프록시). **얕은물**: 2-D 솔버의 실제 높이장 — 벽을 타고 올라 rim 을 넘는 파도.
- HUD: 속도, 종/횡 g, **최소 freeboard**(0 근처면 빨강), 스필 리터, 슬로시 에너지, 켜진
  스태빌라이저, 현재 `experiment.txt` 프로파일. 화면 상단 배너는 녹화(● REC)/재생(▶ REPLAY) 상태.
- 입자·거품·물보라는 없다 (입자 유체는 결정론과 RL 스텝 예산을 깬다). "명백히 출렁이는 액체 덩어리"가
  목표다.
- 차량은 3-DOF 스프렁매스 모델이고 느낌은 "적재 트럭"(무겁고, 긴 제동, 느린 조향)이다. 도로를 켜면
  트럭이 **도로 곡률을 스스로 추종**하고 운전자의 조향은 그 위의 보정이다.

해볼 것:

- 직선에서 매끄럽게 운전하다 완만한 차선 변경 — 표면이 흔들리고 가라앉는다.
- **Space** 로 끄고 하드 제동, 다시 켜고 하드 제동 — freeboard 바와 스필 카운터 비교.
- 빠른 swerve: 반응형 스태빌라이저(1, 2)는 날카로운 입력에 슬로시를 오히려 *펌핑*할 수 있다
  ([findings F1](findings.md)). 매끄러운 운전에서는 도움이 된다 (F2).
- 스태빌라이저 off + 얕은물 모델로 하드 기동하면 짐벌 서보가 슬로시 모멘트에 포화되어 탱크가 30°
  travel 한계까지 처질 수 있다 (진자 모델이나 완만한 운전에서는 안 일어난다).

## 5. 주행 녹화하기

**P** → 운전 → **P**. `Traces/drive-<시각>-<id>.trace.csv` 로 저장되고 콘솔에 전체 경로가 찍힌다.
파일에는 유효 설정 전체와 스텝별 `throttle,brake,steer` 가 들어 있어 시드만으로 같은 주행이 재현된다
([reproducibility.md](reproducibility.md)). 판별력 있는 주행을 원하면 **도로를 켜고(`G`)** 탱크를
꽤 채운 상태(55% 이상)로 녹화한다.

## 6. 3분할 비교 (C)

**C** 를 누르면 최신 녹화 주행을 **① 강체 · ② 규칙기반 · ③ 학습 정책** 세 가지로 동시에 재생한다.
화면이 가로 3칸이 되고 각 칸이 자기 트럭을 보여준다 — **같은 주행, 같은 길, 처리 방식만 다름.**
각 칸에 넘친 리터(크게), rim 근접 시간, 슬로시 에너지 피크, 토크 포화 시간이 표시되고 가장 적게
넘친 칸에 초록 테두리가 둘러진다. 세 칸이 끝나면 아래에 한 줄 판정("① 강체가 가장 적게 넘쳤다 …")이
뜬다. `R` 재시작, `T` 슬로모, 다시 **C** 로 나간다.

③ 칸이 "(offline→Hold)" 면 서버가 없어서 강체로 대체된 것이다 (7절). 그건 AI 성능이 아니라 "서버
없음" 표시다. ④ 천장은 이 비교에 들어가지 않고 키 **5** 로 따로 본다.

## 7. ③ 학습 정책 서버

③ 은 Unity 밖에서 도는 Python 프로세스(`python/serve_policy.py`)가 담당하고, Unity 는 TCP 로
연결한다.

**켜기 (에디터에서 Play 중일 때, 권장):** 설정 패널(`` ` ``) 아래로 스크롤 → **"정책 서버 (③ 학습
정책)"** → **[서버 시작]**. 상태 점이 ○ 꺼짐(주황)에서 ● 실행 중(초록)이 되면 준비된 것이다(1~2 초).
`python/runs/` 아래 가장 최근에 만든 `actor.pt` 를 자동으로 고른다. 그다음 플레이 씬에서 **4** 를
누르면 ③ 이 된다.

**켜기 (터미널, 빌드된 standalone 앱에서는 이 방법뿐):**

```sh
cd python && .venv/bin/python serve_policy.py --checkpoint runs/bc/actor.pt --port 5601
```

터미널 창을 열어 둬야 한다.

**켜졌는지 확인:** 패널 상태등(2초마다 갱신), 또는 ③ 을 켰을 때 HUD 의 "stabilizer:" 줄이
`Learned policy @127.0.0.1:5601` 이면 연결, `… offline → Hold` 면 서버가 없어 강체처럼 동작 중.

**끄기:** 패널에서 켰으면 **[서버 중지]** (Play 를 멈춰도 자동 정리). 터미널에서 켰으면 그 터미널에서
**Ctrl+C**.

체크포인트가 없으면 먼저 학습해야 한다 ([rl.md](rl.md) "실행 방법").

## 8. 라이브 학습 — 새 주행으로 재학습 (K)

**K** 를 누르면 왼쪽에 **라이브 학습** 패널이 열린다.

1. **전제:** 학습에는 `datasets.tsv` 의 `train` 에 **등록된** 주행(도로 켜짐, fill ≥ 0.60)만 쓰인다. **P** 로
   녹화한 새 주행은 자동 등록되지 않는다 — 해시를 구해 등록하는 절차는
   [reproducibility.md](reproducibility.md) 2절. 패널의 "사용 가능한 주행: N건" 이 그 개수다. 공개본에는
   `train` 주행이 없으므로 자기 주행을 등록하기 전에는 시작할 수 없다.
2. **[학습 시작]** — 등록된 `train` 주행 전체로 다시 학습한다. 단계 ①~⑤ 아이콘과 진행률이 실시간으로 찬다.
   ② 천장 탐색이 가장 오래 걸린다.
3. 완료되면 **[정책 서버 (재)시작]**(③ 레인만 새 체크포인트로 교체, 에디터 전용)과
   **[이전 vs 새 정책 비교 시작]** 이 나온다. 후자는 **① 강체 · 이전 정책 · 새 정책** 3레인을 띄운다. 이전
   정책은 패널에서 미리 켜 둔 서버이므로 **그 서버가 먼저 켜져 있어야** 한다. 강체를 함께 넣는 이유는, 새
   정책이 이전보다 나아졌어도 여전히 강체에 못 미칠 수 있어서 그 맥락이 빠지면 오해하기 쉽기 때문이다.
4. 결과는 **4** 또는 **C** 로 본다.

## 9. 결과 로그 (`Logs/episodes-v2.csv`)

3분할 비교와 헤드리스 평가(메뉴 **FluidStabilizer ▸ Evaluate Recorded Drives** / **Evaluate Learned
Policy**)는 끝난 에피소드마다 한 줄을 `Logs/episodes-v2.csv` 에 **덧붙인다** — 운영점(fill·탱크높이·도로·
grip)과 결과(넘친 리터·최소 freeboard·슬로시에너지·액추에이터 노력/포화). 스프레드시트로 열어 실행을
누적 비교할 수 있다. 주행 × 컨트롤러 × 슬로시 모델의 리터 표는 `Logs/trace-eval-<시각>-<id>.txt` 에 쓴다. `Logs/`
는 git 에 안 올라간다.

## 10. standalone 앱 빌드

메뉴 **FluidStabilizer ▸ Build Standalone App** →
`Builds/fluid-stabilizer-StandaloneOSX/fluid-stabilizer.app`. 더블클릭으로 실행. 빌드된 앱에서는 정책
서버를 터미널에서 직접 켜야 한다(7절).

## 11. 문제 해결

| 증상 | 해결 |
|---|---|
| `-executeMethod` / 테스트가 멈춰 있음 | Unity 에디터를 닫고 `Temp/UnityLockfile` 삭제. Unity 는 프로젝트당 하나만 열림 |
| 설정 패널 [적용] 했는데 안 바뀜 | HUD 왼쪽 위 프리셋/값 확인. 재생(`L`) 중이면 트레이스가 우선이라 무시됨 |
| ③ 서버가 계속 "꺼짐" | 포트 5601 충돌? 터미널에서 `lsof -iTCP:5601` 확인. 체크포인트가 있나? `python/runs/` |
| 서버 [시작] 이 "체크포인트 없음" | 먼저 학습 필요. [rl.md](rl.md) "실행 방법" |
| 빗길/눈길에서 안 미끄러짐 | 급브레이크·급조향을 해야 한계를 넘는다. 미끄러지면 HUD 에 "⚠ 타이어 미끄러짐". 눈길(grip 0.38)이 빗길(0.6)보다 잘 미끄러짐 |
| 미끄러질 때 너무 홱홱 돌아 운전이 안 됨 | "미끄러짐 격렬함" 슬라이더를 낮춘다(기본 0.5). 더 거세게: `experiment.txt` `slipIntensity: 1.5` 이상 |
