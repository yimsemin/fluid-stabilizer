> 이 문서는 **다른 모니터**에 띄워두고 보는 용도다. 메인 모니터에서는 프로그램을
> 직접 시연한다. 청중은 비개발자이고 Physical AI 를 이제 막 공부하기 시작한
> 사람들이라고 가정한다.

> 사실의 숫자·근거는 [findings.md](findings.md), 설계 근거는

## 한눈에

- **무엇:** 사람이 운전하는 트럭에 **뚜껑 없는 물탱크**가 실려 있다. 급제동·
  코너링·범프에 물이 출렁여 넘친다. 탱크 아래 **2축 받침대(스태빌라이저)** 를
  AI 가 제어해서 넘침을 줄이려는 시뮬레이션.
- **AI 는 운전하지 않는다.** 운전자는 AI 가 대응해야 할 외부 교란일 뿐.
- **목적:** "물리 → 센서 → 액추에이터 → 컨트롤러 → 학습 정책 → 평가" 파이프라인
  **전체를 직접 만들며 Physical AI 를 이해**하는 것. 화려한 결과물보다 이해가
  우선. (실제 로봇은 아직 못 사니 시뮬레이션이 로봇을 대신한다.)

## 1. 왜 어려운가 — 슬로시(sloshing)의 시간 동역학

물컵을 들고 걷다 멈춰도 물은 계속 앞뒤로 출렁인다. 이게 문제의 핵심이다:

- **기동이 끝나도 액체는 계속 움직인다.** "지금 가속에 맞춰 탱크를 기울이기"
  같은 반사적 대응으로는 부족하다 — 뒤이어 올 파도를 **예측(anticipation)**
  해야 한다.
- **부분 관측.** AI 는 물 입자 위치나 정확한 무게중심을 볼 수 없다. 실제 센서가
  줄 수 있는 것(IMU, 받침대 각도, 로드셀 등, 노이즈·지연 포함)만 보고 숨은 액체
  상태를 **추론**해야 한다.
- **비이상적 액추에이터.** 받침대 모터는 토크·각속도·각도 한계가 있고, 오래 세게
  쓰면 과열되어 힘이 줄고, 명령에 지연이 있다.

> 반사적 대응이 **오히려 해로울 수 있다:** 파도에 맞춰 탱크를 급히 돌리면
> 슬로시 에너지를 *더* 넣어 넘침이 늘어난다 (아래 F1).

## 2. 구조 — 세 덩어리 + 비교 대상

실제 로봇은 **몸 / 뇌 / 학습 장비**가 분리되어 링크로 대화한다. 시뮬도 그렇게 나눴다.

| 덩어리 | 무엇 | 어디 |
|---|---|---|
| **세계 + 몸** | 차량·도로·탱크·슬로시·액추에이터·센서. 센서값을 내보내고 명령을 받음 | Unity 앱 (`Assets/FluidStabilizer/`) |
| **뇌** | 학습된 정책. 센서값 → 행동 | 별도 Python 프로세스 (`python/serve_policy.py`), TCP 로 연결 (= 나중 ROS 2 자리) |
| **학습 장비** | PPO 강화학습, 행동 복제 | 오프라인 Python (`python/train_ppo.py` 등). 시연과 절대 같이 안 돎 |

물리 계산은 게임 엔진(PhysX)이 아니라 **직접 짠 C# 코드**로 고정 시간간격
(600 Hz)에 적분한다 → Mac/Windows 어디서나 **같은 결과**(결정론), 유닛 테스트
가능, RL 스텝이 빠름.

**비교 대상 (같은 주행을 이 방식들로 처리해 넘친 양을 비교):**

| | 방식 | 한 줄 설명 |
|---|---|---|
| ① | **강체 (Rigid)** | 탱크를 트럭에 볼트로 고정. 스태빌라이저 없음. 바닥선(baseline). |
| ② | **규칙 기반 (PID)** | "느껴지는 기울기에 맞춰 탱크를 반대로 기울여라" 고정 법칙. |
| ③ | **학습 정책** | 소유자 주행으로 (부분) 학습한 RL. |
| ④ | **후행지식 천장 (hindsight)** | 주행 전체를 미리 다 알고 오프라인 최적화한 받침대 궤적. "이론상 최선" — 실제로는 불가능(미래를 알아야 하므로), 비교용 상한선. |

## 3. 학습은 어떻게 시키나

```
녹화 주행  →  후행지식 천장  →  행동 복제(BC) 웜스타트  →  잔차 RL(PPO)  →  체크포인트  →  serve_policy.py
 (사람이     (미래를 다 알면      (천장 궤적을 흉내내게      (베이스라인 위에      (.pt 파일)     (뇌 프로세스로
  운전)       얼마나 잘하나)        정책망 사전학습)          작은 보정만 학습)                    서빙)
```

1. **녹화 주행** — 플레이 씬에서 `P` 를 눌러 직접 운전한 주행을 파일로 저장
   (`Traces/drive-*.trace.csv`). throttle/brake/steer 만 저장하면 나머지는
   결정론이라 완전히 재현된다. 이게 학습·평가의 단위 = "한 번의 주행".
2. **후행지식 천장 (④)** — 한 녹화 주행에 대해, 주행 전체를 미리 알고 받침대
   궤적을 오프라인 최적화한다. "예측이 완벽하다면 얼마나 줄일 수 있나"의 상한선.
   **이게 결정 게이트:** 이 천장조차 강체(①)를 못 이기면, 인과적(미래를 모르는)
   정책은 절대 못 이긴다 → 전제를 바꾸기 전엔 긴 학습을 하지 않는다.
3. **행동 복제 (BC) 웜스타트** — 천장 궤적을 흉내내도록 정책 신경망을 지도학습으로
   사전 초기화. 처음부터 무작위로 시작하면 탐색이 "F1 절벽"으로 떨어지므로,
   얌전한 시작점을 준다.
4. **잔차 RL (PPO)** — 정책이 **베이스라인(잠근 탱크 등) 위에 작은 보정만**
   강화학습한다. 처음부터 전부 배우는 "맨땅 PPO"는 이 문제를 못 배운다 (아래
   RL 첫 실행 결과).
5. **체크포인트 → 서빙** — 학습된 가중치(`.pt`)를 `serve_policy.py` 가 로드해
   별도 프로세스로 추론을 서빙. Unity 는 TCP 로 센서값을 보내고 행동을 받는다.
6. **현재 상태:** 위 파이프라인은 전부 배선·검증됐지만, **긴 잔차 RL 학습은
   보류 중**이다 — 2번 게이트를 통과하지 못했다 (아래 5절).

> **왜 맨땅 PPO 가 안 되나 (RL 첫 실행, F1/F4):** 무작위로 시작한 정책의 짐벌
> 동작이 슬로시를 펌핑해 모든 시도가 일찍 넘쳐 끝난다 → "전부 똑같이 나쁨" 을
> 학습 → 경사가 사라지고 학습이 멈춘다. 좋은 정책은 좁은 "가만히/예측" 능선
> 위에만 있어서 무작위 탐색으로는 못 찾는다.

## 4. 학습된 것 vs 베이스라인 비교

플레이 씬에서 **`C`** 키 → **3분할 화면**. 최신 녹화 주행을 세 트럭이 **동시에**
재생한다:

- 세 트럭 모두 **같은 녹화 주행(같은 조향·제동), 같은 도로**. 다른 건 처리 방식뿐.
- 위 = ① 강체, 가운데 = ② PID, 아래 = ③ 학습 정책 (`serve_policy.py` 안 켜졌으면
  "(offline → Hold)" 로 강체 폴백).
- 각 칸 패널: **넘친 리터**(크게), rim 근접 시간, 슬로시 에너지 피크, 토크 포화
  시간. 가장 적게 넘친 칸에 **초록 테두리**.
- 세 칸이 다 끝나면 아래에 **한 줄 판정**: "① 강체가 가장 적게 넘쳤다 (…)" 또는
  "레인 간 차이 거의 없음".

**배치 수치:** 메뉴 ▸ *FluidStabilizer ▸ Evaluate Recorded Drives* (또는
*Evaluate Learned Policy*) → 모든 녹화 주행 × 컨트롤러 × 슬로시 모델의 리터 표를
`Logs/trace-eval.txt` 에 쓰고, 에피소드마다 한 줄을 **`Logs/episodes.csv`** 에
덧붙인다 (운영점 + 결과 지표 → 스프레드시트로 누적 비교·그래프).

## 5. 결과를 어떻게 읽나

- **1차 지표 = 넘친 리터.** 부가 지표: rim 근접 시간, 슬로시 운동에너지 피크,
  액추에이터 노력/열부하.
- **헤드라인 벤치마크 = 소유자 자신의 녹화 주행** (합성 시나리오 아님). 홀드아웃
  주행에서 주행별 리터로 본다.
- **브래킷 규율:** 슬로시 모델 2종 — 싼 **진자 ROM**(학습·빠른 반복용)과
  정밀한 **얕은물 솔버**(검증용). 정책이 진자에서만 이기면 그건 모델
  아티팩트일 가능성이 높다 → 두 모델 모두에서 유지될 때만 인정.

### 지금까지의 결과 — **① 강체가 이긴다**

| 발견 | 내용 |
|---|---|
| **F1 / F4** | 어떤 반응형 틸트 컨트롤러(PID 포함, LQR 포함)도 강체(①)를 못 이긴다. 반사적으로 탱크를 돌리면 슬로시를 펌핑한다. |
| **F5** | 완전한 후행지식(④) 짐벌 궤적조차 녹화 주행에서 강체보다 **더** 넘친다. 0 을 명령하는 서보가 이미 잠근 관절에 5~7 L 진다. |
| **F6** | 그 구조적 핸디캡을 없애는 **lock-capable 하이브리드 액션**(D8: 필요없을 때 기계적으로 잠김)을 주고, 11개 운영점(fill 0.50~0.62, 도로 강도, 노면 마찰)에서 게이트를 재실행 — **여전히 강체를 못 이긴다.** 강체가 조금이라도 넘치는 모든 fill 에서 후행지식이 회복하는 건 스필의 **1~2%** 뿐. |

**해석:** 소유자가 실제로 녹화한 주행에서는 능동 2축 안정화가 탱크를 볼트로
고정하는 것보다 나을 여지가 없다. 이건 실패가 아니라 **결과**다 — 파이프라인
전체를 제대로 만들었기 때문에 이 결론을 방어할 수 있다.

### 그런데 예외를 하나 찾았다 (F8, 2026-09-10)

2c 스윕은 녹화 주행 위에 탱크·노면만 바꿨을 뿐, **운전 자체**는 고정이었다.
운전 축을 합성 주행으로 훑자 한 곳에서 게이트가 **처음으로 PASS** 했다 —
**매끄러운 노면(도로 off)의 지속 코너링.** 같은 시연 주행에서 스필 [L]:

| | 진자 | 얕은물 |
|---|---|---|
| ④ 천장 (후행지식) | **5.1** | **7.9** |
| ① 강체 | 7.9 | 24.9 |
| ② 규칙기반 (PID / SFA) | 25.2 / 25.8 | 52.4 / 45.0 |

두 가지를 동시에 말한다.

1. **이길 수 있는 조건이 존재한다.** 지속 코너링은 저주파 단일축 외란이라
   rate 제한 짐벌이 추종할 수 있다. 노면을 0.3× 만 켜도 이득이 사라진다 —
   **광대역 노면**이 F5/F6 를 만드는 진짜 전제다.
2. **지금의 규칙기반은 그 이득을 못 가져간다.** ②는 강체보다 3 배 나쁘고
   토크를 94~100 % 포화시킨다. 천장(5 L)과 최선의 인과적 컨트롤러(25 L) 사이
   **20 L 의 간극** — 이 프로젝트에서 처음으로 "학습이 메울 여지"가 실제로
   측정된 것이다.

헤드라인은 그대로다: **소유자의 실제 녹화 주행에서는 ① 강체가 이긴다.**
F8 은 합성 시연 조건이지 소유자의 주행이 아니다.

## 6. 시연 중 눌러볼 것 (메인 모니터)

플레이 씬: 메뉴 ▸ *FluidStabilizer ▸ Rebuild Play Scene* 후 그 씬을 Play.

| 키 | 무엇 | 보여줄 것 |
|---|---|---|
| **W/S · A/D** | 가감속 · 조향 | "적재 트럭" 느낌 — 무겁고, 긴 제동, 느린 조향 |
| **Space** | 스태빌라이저 on/off | 하드 제동을 off 로 한 번, on 으로 한 번 → freeboard 바·스필 카운터 비교 |
| **0~5** | 스태빌라이저 선택 | 0 강체 · 1 SFA · 2 +적분 · 3 특권 feed-forward(치트) · 4 학습 정책 · **5 천장(④, 후행지식 재생)** |
| **` (백틱)** | 컨트롤 패널 | 도로 프리셋(일반/비포장/굽은길/급경사/빗길/눈길) + 슬라이더 → [적용] |
| **G** | 도로 on/off | 평평 ⇄ 굽이치는 grade·bank·거칠기·포트홀 |
| **M** | 슬로시 모델 | 진자 ROM ⇄ 얕은물 (얕은물은 실제 파도가 벽을 타고 rim 을 넘음) |
| **P / L** | 주행 녹화 / 재생 | 짧게 녹화 → `L` 재생하며 `0~4` 로 스태빌라이저 전환 |
| **C** | 3분할 비교 | 4절 참고. 데모의 하이라이트. |
| **T · Tab** | 슬로모 · 카메라 | 출렁임을 천천히, 각도 바꿔서 |

권장 흐름: ① 직접 운전(느낌) → ② Space on/off 하드 제동(차이) → ③ 컨트롤 패널로
빗길 프리셋 적용(교란 키우기) → ④ `C` 3분할(헤드라인 결과) → ⑤ (선택) `M` 얕은물로
바꿔 파도 시각화.

### 학습된 정책(③)까지 보려면

`python/runs/bc-f8/actor.pt` 가 이 조건에서 학습된 정책이다 (천장 궤적을 BC 로
클론). 터미널에서:

```sh
cd python && .venv/bin/python serve_policy.py --checkpoint runs/bc-f8/actor.pt --port 5601
```

띄운 뒤 플레이 씬에서 **4** 를 누르면 ③ 레인이 실제 정책으로 돈다 (서버가 없으면
자동으로 강체 Hold 로 떨어지고 화면에 그렇게 표시된다 — 그건 AI 성능이 아니다).

같은 주행 스필 [L]: ④ 천장 **5.1** · ① 강체 **7.9** · **③ 학습 12.4** ·
② 규칙기반 25.2. **③ 이 규칙기반을 51 % 앞선다** — 이 프로젝트에서 ③ 이 무언가를
학습했다는 최초의 증거다. 다만 **강체에는 여전히 진다** (findings F10).

   시연용 주행과 그 주행의 최적 궤적을 `Traces/demo-corner-*.trace.csv` /
   `.traj.csv` 로 만들고, 콘솔에 위 표를 그대로 찍는다. (합성 조건이라
   `datasets.tsv` 에는 넣지 않는다 — [reproducibility.md](reproducibility.md))
2. 플레이 씬에서 **L** 로 그 주행을 재생.
3. **0** (강체) → **5** (천장) 를 번갈아 누르며 스필 카운터 비교.
   **1/2** (규칙기반)도 눌러 보면 오히려 크게 나빠지는 걸 볼 수 있다.
   정책 서버를 띄웠다면 **4** (학습 정책)도 — 규칙기반보다 확실히 낫고
   강체보다는 못한 중간 위치다.
4. **M** 으로 얕은물로 바꾸면 차이가 훨씬 커진다 (24.9 → 7.9 L).

**주의 — 정직하게 말할 것:** 5 번 레인(④)은 컨트롤러가 아니라 **주행 전체를
미리 알고 오프라인에서 계산한 최적해의 재생**이다. "이만큼은 가능하다" 는
상한이지, 실시간으로 달성했다는 뜻이 아니다.

## 7. 앞으로 남은 개발 과제

- **전제 조정 후 긴 잔차 RL.** F6 게이트를 통과하려면 전제를 바꿔야 한다:
  (a) 탱크 형상(더 깊게/넓게) 또는 (b) 강체가 1~5 L 만 넘치는 **얌전한 홀드아웃
  주행** 녹화. 그 위에서 BC 웜스타트 + 잔차 PPO 를 실제로 길게 (2 시드 × ~2.5M
  스텝) 돌려 ①②③④ 리터 비교. `train_ppo.py --resume` 로 체크포인트 재개 가능.
- **`RemotePolicyController` 잔차 서빙.** 지금 서빙 경로는 "맨" 정책만 지원.
  lock-capable 잔차 정책을 서빙하려면 클라이언트가 베이스라인 합성 + `LockGate`
  를 로컬로 돌려야 함.
- **도메인 랜덤화 + 에피소드별 파라미터 로깅** (config 구조체는 있음, 랜덤화기
  미구현). 활성 RL 학습 재개 시 함께.
- **액추에이터·센서 정밀도 상향** — 백래시·기어박스 상세, 센서 모델을 실제
  데이터시트에 보정.
- **학습기 GUI** — 실험 관리·진행 모니터링용 작은 화면.
- **Phase 3: ROS 2 브릿지 + 실제 하드웨어.** 설계가 이미 메시지 DTO + 인터페이스
  경계를 유지하고 있어 재구조화 없이 붙일 수 있게 되어 있음.

## 용어 (Physical AI 입문 청중용)

| 용어 | 뜻 |
|---|---|
| **슬로시 (sloshing)** | 용기 안 액체의 출렁임. 여기서는 그 *시간 동역학*(기동 후에도 계속 움직임)이 문제. |
| **freeboard** | 액체 표면에서 탱크 rim 까지 남은 높이. 0 이하 = 넘침. |
| **베이스라인 (baseline)** | 학습 정책과 비교할 기준. ① 강체, ② 규칙 기반. |
| **후행지식 (hindsight)** | 미래를 다 알고 나서(사후에) 최적화. 실제로는 불가능, 이론상 상한선. |
| **잔차 RL (residual RL)** | 정책이 베이스라인 행동 위에 *작은 보정*만 학습. 전부 배우는 것보다 안정적. |
| **행동 복제 (BC)** | 좋은 시범(여기선 후행지식 궤적)을 흉내내도록 지도학습으로 정책을 초기화. |
| **비대칭 actor-critic** | 학습 중 가치망(critic)은 ground truth 를 봐도 되지만, 실제 행동하는 정책(actor)은 센서만 본다. |
| **결정론 (determinism)** | 같은 입력 → 항상 같은 결과. 재현·디버깅·공정한 비교의 전제. |
