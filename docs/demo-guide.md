# 시연 가이드

> 다른 모니터에 띄워 두고 보는 용도다. 청중은 비개발자이고 Physical AI 를 이제 막 공부하는 사람들이라고
> 가정한다. 키·버튼 조작은 [operating-guide.md](operating-guide.md), 결과와 교훈은
> [lessons.md](lessons.md), 용어는 [docs/README.md](README.md) 에 있다.

## 청중에게 먼저 할 설명 (1분)

- 사람이 운전하는 트럭에 **뚜껑 없는 물탱크**가 실려 있다. 급제동·코너링·요철에 물이 출렁여 넘친다. 탱크 아래
  **2축 받침대(스태빌라이저)** 를 AI 가 제어해 넘침을 줄이려는 시뮬레이션이다. AI 는 운전하지 않는다.
- 어려운 점: 기동이 끝나도 물은 계속 출렁이고(**시간 동역학**), AI 는 물의 상태를 직접 볼 수 없고 센서값
  (노이즈·지연 포함)으로 **추론**해야 하며, 받침대 모터는 힘·속도·각도에 한계가 있다.
- 구조: 차량·탱크·센서가 있는 **Unity 앱(몸)**, 학습된 정책이 도는 **별도 Python 프로세스(뇌)**, 오프라인
  **학습 장비**로 나눠 로봇처럼 링크로 대화한다.
- 같은 주행을 네 가지로 처리해 **넘친 리터**를 비교한다: ① 강체(탱크를 볼트로 고정, 아무것도 안 함) ·
  ② 규칙기반 · ③ 학습 정책 · ④ 천장(주행 전체를 미리 아는 오프라인 최선, 실제로는 쓸 수 없는 기준선).
- 목적은 결과물보다 **파이프라인 전체를 직접 만들며 이해하는 것**이다.

## 시연 전 준비

1. Unity 로 프로젝트를 열고 메뉴 **FluidStabilizer ▸ Rebuild Play Scene**.
2. **(F8 예외를 보여줄 때만) FluidStabilizer ▸ Generate Demo Drive (sustained corner)** — 약 3분 걸린다.
   미리 해 둔다. `Traces/demo-corner-*.trace.csv` 와 `.traj.csv` 가 생긴다.
3. **`L`·`C` 는 `Traces/` 에서 가장 최근에 수정된 파일을 재생한다.** 클론 직후에는 7 개의 `final` 주행 중
   어느 것이 재생될지 정해져 있지 않고, 2번을 하면 합성 주행 `demo-corner` 가 가장 최근이 된다. 보여 주려는
   파일을 `touch` 로 최신으로 만든 뒤 재생한다.
4. 공개본에는 학습 체크포인트가 없다([reproduce-from-scratch.md](reproduce-from-scratch.md)). ③ 레인은
   "(offline→Hold)" 로 뜨고 ① 강체와 같은 값이다. ③ 은 말로만 설명한다.

### F8 예외 보기 (권장 마무리)

합성 주행(매끄러운 노면의 지속 코너링) `demo-corner` 를 `L` 로 재생하고 **`0`(강체)과 `5`(천장)를 번갈아**
누른다. 스필 [L]:

| | 진자 | 얕은물 |
|---|---|---|
| ④ 천장 | **5.1** | **7.9** |
| ① 강체 | 7.9 | 24.9 |
| ② 규칙기반 (PID / SFA) | 25.2 / 25.8 | 52.4 / 45.0 |

`1`·`2`(규칙기반)를 눌러 보면 강체보다 크게 나빠지고, `M` 으로 얕은물로 바꾸면 차이가 더 커진다.
말할 것: (1) 이길 수 있는 조건이 있다 — 지속 코너링은 저주파 단일축 외란이라 속도 제한이 있는 짐벌도 따라갈
수 있고, 노면을 0.3× 만 켜도 이득이 사라진다(진짜 전제는 **광대역 노면**). (2) 지금의 규칙기반은 그 이득을
못 가져간다(강체보다 3배 나쁘고 토크를 94~100 % 포화). 값은 진자 5.10 / 7.91 / 25.22 / 25.75 L 로 재현을
확인했다(출처 [F8](findings.md)).

**정직하게 말할 것:** ④ 는 컨트롤러가 아니라 **주행 전체를 미리 알고 오프라인에서 계산한 궤적의 재생**이다.
"이만큼은 가능하다"는 기준선이지 실시간으로 달성했다는 뜻이 아니다. 이 주행은 합성 시연 조건이지 녹화 주행이
아니다.

## 결론

[lessons.md](lessons.md) "한 문단 요약"을 그대로 말한다. 한 줄로: **제어보다 탱크 설계가 먼저.** 짐벌에는 속도·토크
한계와 지연이 있어 빠른 도로 외란을 따라가지 못하고 오히려 액체를 더 흔든다. 학습이 안 되던 원인은 액션 공간이었다.
배플의 손실 계수가 실제 어떤 배플인지는 확인하지 못했다([F16](findings.md)).

## 예상 질문

- **더 학습시키면 이기나?** 시도했고 닫혔다 — 교사 주행 늘리기(F11)와 DAgger(F12)로도 못 이겼다.
- **예측 제어(MPC)는?** 정답 상태와 정확한 모델을 준 오라클도 강체 대비 −5 ~ −8 % 였다(F14).
- **실제 로봇은?** 메시지 DTO 와 인터페이스 경계를 유지해 ROS 2 나 하드웨어를 붙일 수 있게 했지만, 시뮬레이션에서
  이득이 확인된 뒤의 단계다.
- **다음에 해볼 것은?** 배플 손실 계수가 실제 배플에 해당하는지 확인하는 것([lessons.md](lessons.md) 후속
  제언 1).
- **학습 용어:** *행동 복제(BC)* — 좋은 시범을 흉내 내도록 지도학습으로 정책을 초기화. *잔차 RL* — 베이스라인
  위에 작은 보정만 학습. *비대칭 actor-critic* — 학습 중 평가자(critic)는 정답을 봐도 되지만 행동하는 정책은
  센서만 본다. *결정론* — 같은 입력이면 항상 같은 결과(재현·공정한 비교의 전제).
